# User Confirmation Policy

모든 세션·스쿼드·역할 에이전트에 적용한다. Product Owner 또는 다른 에이전트의 승인은 사용자 확인을 대체하지 못한다.

## 1. 사용자 확인이 필요한 작업

### 중요 정책

- 사업 방향, 수익 모델, 광고 정책, KPI, 로드맵, 우선순위
- 사용자 역할, 권한, 가입, 인증, 개인정보, 보존·삭제
- 상담 생성·배정·이관·종료·재개·차단
- 대학 등록·계정 발급·공개·게시·노출 정책
- 콘텐츠 작성·검토·게시·광고 구좌 운영
- 스쿼드 구조, 파일 소유권, 공통 데이터 계약
- 여러 스쿼드에 영향을 주는 URL·상태·schema·분석 이벤트
- 대규모 파일 이동, 삭제, 마이그레이션, 배포

### 모호한 요청

- 둘 이상의 합리적 해석이 있고 결과가 달라지는 요청
- 대상 사용자, 범위, 소유 스쿼드, 완료 조건이 불명확한 요청
- 기존 결정이나 제품 원칙과 충돌할 가능성이 있는 요청
- 요청 범위를 넘어서는 수정이 필요한 작업

## 2. 확인 전 허용

- 읽기 전용 조사
- 현재 상태와 충돌 확인
- 가능한 해석·선택지·권고안 작성
- 영향받는 스쿼드·파일·계약·위험 식별
- 사용자 확인 질문

## 3. 확인 전 금지

- 파일·코드·정책·결정 문서 수정
- 구현·리팩터링·파일 이동·삭제
- 외부 시스템 변경·배포·메시지 발송
- 제안 상태를 확정 또는 완료 상태로 변경
- 모호한 부분을 임의 가정해 실행

## 4. 사전 확인 요청 형식

다음을 짧게 제시한다.

1. 요청을 어떻게 이해했는지
2. 제안하는 결정 또는 변경
3. 영향받는 스쿼드·사용자·파일·계약
4. 선택지와 권고안
5. 위험·제외 범위
6. `이 내용으로 진행해도 될까요?`

사용자의 명시적인 승인 표현이 있어야 진행한다. 침묵, 주제 변경, 모호한 긍정은 승인으로 취급하지 않는다.

## 5. 작업 중 범위 변경

승인받은 해석·범위·정책이 달라지면 즉시 중단하고 다시 확인받는다. 일반 승인은 새 중요 정책이나 확대된 범위에 재사용하지 않는다.

## 6. 완료 확인

중요 정책 또는 모호했던 요청의 작업 완료 후 다음을 보고한다.

- 실제 결정·변경
- 변경 파일·영향 범위
- 검증 결과
- 승인안과 달라진 점
- 남은 위험·후속 작업

사용자가 결과를 확인하기 전에는 중요 정책 작업을 최종 확정·종료로 표시하지 않는다.

## 7. 예외

다음은 추가 확인 없이 진행할 수 있다.

- 읽기 전용 상태 확인
- 이미 사용자 승인된 범위 안의 명백한 구현
- 의미가 변하지 않는 오탈자·링크 수정
- 안전하고 되돌릴 수 있는 검증

단, 작업 중 중요 정책 변경이나 새로운 모호성이 발견되면 확인 게이트로 전환한다.
