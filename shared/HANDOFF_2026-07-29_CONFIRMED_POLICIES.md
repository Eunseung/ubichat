## 용어

- `affiliationId`: **소속구분 식별값**. 같은 대학의 학부/학사·언어교육원·대학원을 구분하는 내부 값이다.
- `university-publication` v2: 학교가 소속구분별 공개정보를 메인·학생 화면에 전달할 **공통 데이터 형식**이다. 새 기능이나 별도 운영 화면을 뜻하지 않는다.
- `unitOwnerId`: 기존 계약의 “소속구분 관리자 1명” 값이다. 현재 정책은 복수 관리자를 허용하므로, 계약 확정 시 `unitOwnerIds[]` 목록으로 바꾼다.

## 모든 스쿼드 공통

1. 대학별 최고관리자는 1명이다. 소속구분 관리자와 멤버는 여러 소속구분에 동시에 배정될 수 있다.
2. 최고관리자는 모든 소속구분을, 소속구분 관리자와 멤버는 배정된 모든 소속구분을 업무 범위로 가진다.
3. 최고관리자·소속구분 관리자·멤버 모두 배정된 소속구분의 공개정보·로고·배경·사진·브로셔를 직접 게시할 수 있다. 어드민은 대학 등록을 승인하지만 공개 자산을 사전 승인하지 않는다.
4. 학생 탐색의 공개 단위는 `universityId + affiliationId`다. 대학과 해당 소속구분이 모두 `published`일 때만 카드 1개를 노출한다.
5. 상담 채널은 `studentId + universityId + affiliationId`별로 독립한다. 같은 학생의 학부·어학원·대학원 상담은 별도 목록·별도 이력으로 표시한다. 대학 관계자는 배정 소속구분의 채널만 보고, 복수 소속구분 권한자는 각 채널을 모두 본다.
6. 차단과 차단 해제는 `studentId + universityId + affiliationId` 채널에서 실행한다. 모든 대학 구성원은 배정 소속구분 범위에서만 실행할 수 있다. 해제 사유는 필수이며, 해제 뒤 학생은 해당 소속구분에만 재상담할 수 있다.
7. 학생 유치 홍보 페이지와 `등록 문의`는 D-010에 따라 보류한다. 설계·구현·분석 이벤트를 진행하지 않는다.
8. 모든 공개·학생 GNB의 UBIChat 로고는 `기업용_배너_포함.html`로 이동한다. 비로그인은 `대학 탐색 · 상담하기 · 콘텐츠`, 로그인 학생은 `대학 탐색 · 내 상담 · 콘텐츠`를 같은 순서로 표시한다.
9. 프로토타입의 현재 대학은 모두 공개한다. 공개 소속구분 더미가 없는 대학은 `undergraduate` 기본 소속구분 카드 1개를 사용한다. 이는 프로토타입 전용이며 실서비스 공통 계약에는 넣지 않는다.
10. 공식 서비스 표기는 `UBIChat`이다. 기존 `unichat` 저장소 키·이벤트·전역 API·스타일 클래스·파일명은 내부 호환용으로 유지하며 사용자 화면에 노출하지 않는다.

## 학생 스쿼드

- 공개 상세→로그인·가입→학생 포털→소속구분별 독립 상담 채널까지 `universityId`, `affiliationId`를 모두 보존한다.
- 차단 학생은 차단된 소속구분에만 재상담할 수 없고, 차단 해제 뒤 해당 소속구분에서 재상담할 수 있다.
- 대학의 서류 요청 시 일치하는 등록 문서 또는 새 파일을 학생이 전송 전 미리보기에서 확인한 뒤 전달한다.
- 학교의 수신 문서 `재요청하기`는 같은 소속구분 채널에 재업로드 상자를 만든다. 학생은 새 PDF 업로드 또는 같은 유형의 기존 문서 선택으로 전송하며, 학교 우측 패널은 빨간 점과 `업데이트됨`으로 표시한다.
- PDF 파일당 10MB 이하만 업로드한다. 외부 클라우드 링크는 `기타` 분류의 HTTPS 링크만 저장·표시하며 파일을 복제·색인하지 않는다.

## 학교 스쿼드

- 한 운영 화면에서 배정된 소속구분의 독립 상담 채널·공개정보를 관리한다. 소속구분별 별도 운영 페이지를 만들지 않는다.
- 멤버를 포함한 모든 역할자는 배정된 소속구분의 공개정보·자산을 직접 게시할 수 있다.
- 채팅 목록에서 차단·차단 해제를 제공한다. 해제 사유는 필수이며, 행위자·시각·대상·사유를 감사 데이터로 넘긴다.
- 소속구분별 공개 표시명, 게시 상태, 소개·과정·혜택, 자산, 상담 상태·운영시간을 공통 계약 생산 데이터로 연결한다.
- 웰컴 메시지·이미지는 소속구분별 독립 상담 채널의 신규 상담 또는 재문의 회차 시작 뒤 1회만 보낸다. 공개 상세에는 표시하지 않는다.
- 학생의 서류 요청을 만들고, 학생이 전송을 확인한 등록 문서 또는 업로드 문서를 수신한다.
- 수신 문서별 `재요청하기`를 제공하고, 재업로드는 같은 학생·대학·소속구분 우측 패널에 업데이트 알림으로 표시한다.

## 메인·탐색·콘텐츠 스쿼드

- 공개 소속구분마다 카드 1개를 만든다. 예: `서정대학교`, `서정대학교 언어교육원`, `서정대학교 대학원`.
- 카드명은 소속구분 공개 표시명을 사용하고, 상세·상담 CTA까지 선택 `affiliationId`를 유지한다.
- 상세는 선택 소속구분의 공개 정보·자산만 표시한다. 자산·필드 없음은 안전한 기본·빈 상태로 처리한다.
- 학교 내부 `operatingProfiles`를 읽지 않는다. 프로토타입에서는 D-017에 따라 공개 소속구분 더미가 없는 대학에 `undergraduate` 기본 소속구분 카드 1개를 만들며, 실서비스 계약에서는 학교가 직접 게시한 소속구분만 사용한다.
- 웰컴 메시지·이미지를 공개 상세에 표시하지 않는다. 상담 CTA는 선택 소속구분의 독립 채널로 연결한다.

## 어드민 스쿼드

- 대학 등록 신청 승인·반려와 최고관리자·소속구분 관리자·멤버 계정 발급을 담당한다.
- 공개 프로필·자산 승인 큐를 만들지 않는다.
- 학생 문서 원본과 메시지 본문은 기본 열람 대상이 아니다. 서류 요청·업로드·전달의 화면·전송 처리는 학생·학교 스쿼드 범위다.
- 차단 해제 사유는 학교 채널의 필수 입력이다. 어드민 차단 이력 화면은 이번 즉시 작업 범위가 아니다.

## 공통 계약 선행 작업

`shared/contracts/university-publication.md`는 학교 Developer가 Steward다. 필수 검토 완료 뒤 다음을 반영한다.

- 소속구분별 복수 관리자와 복수 멤버, 한 계정의 복수 소속 배정
- 소속구분별 `published` 상태와 공개 표시명
- 소속구분별 공개 상세 정보·자산·상담 상태·운영시간
- 메인→학생의 `universityId`, `affiliationId` 전달 및 소속구분별 독립 채널 식별

계약이 확정되기 전에는 메인이 학교 내부 상태를 직접 소비하지 않으며, 학교·학생·메인은 더미를 실서비스 연동 완료로 표시하지 않는다.

## 완료 확인

- 학교: 각 역할·배정 소속구분에서 직접 게시와 차단·사유 필수 해제를 확인한다.
- 메인: 공개 조건, 카드·상세·CTA의 `affiliationId` 보존, 빈 상태를 확인한다.
- 학생: 로그인·가입 반환, 소속구분별 독립 채널·목록, 차단·해제 뒤 재상담, 문서 요청 전달을 확인한다.
- 어드민: 대학 등록·계정 발급·차단/해제 감사 이력을 확인한다.
