# UBIChat 공통 데이터 계약 요약

이 문서는 정적 프로토타입의 스쿼드 간 인터페이스 기준이다. 실제 API schema 확정본은 아니다.

## 1. 공통 식별자

| 대상 | 필수 식별자 |
|---|---|
| 대학 | `universityId` |
| 대학 소속구분 | `universityId + affiliationId` |
| 상담 채널 | `studentId + universityId + affiliationId` |
| 문서 요청·전달 | `requestId + studentId + universityId + affiliationId` |
| 플랫폼 공지 | `noticeId + audience + status` |

대학명·소속구분명 문자열을 식별자로 사용하지 않는다.

## 2. 대학 공개정보

```text
UniversityPublic
├─ universityId
├─ universityName
├─ universityPublicationStatus: published | hidden
└─ affiliations[]
   ├─ affiliationId
   ├─ displayName
   ├─ publicationStatus: published | hidden
   ├─ fields[]
   ├─ profile
   │  ├─ headline
   │  ├─ detail
   │  ├─ departmentInfo
   │  ├─ applicationProcess
   │  └─ dormitory
   ├─ assets
   │  ├─ logo
   │  ├─ heroImage
   │  ├─ universityPhotos[]
   │  ├─ admissionGuidePdf
   │  └─ dormitoryPhotos[]
   ├─ tabs[]
   │  ├─ id
   │  ├─ kind
   │  ├─ title
   │  ├─ content
   │  ├─ order
   │  └─ enabled
   ├─ publicInfo.website.url
   ├─ publicInfo.locationAddress
   └─ consultation
      ├─ status: open | offline | paused
      ├─ responseLabel
      ├─ hours
      └─ languages[]
```

- 카드 노출 조건은 대학과 소속구분이 모두 `published`인 경우다.
- 공개 상세는 선택된 소속구분 데이터만 표시한다.
- `website.url`은 HTTPS만 허용한다.
- 공식 홈페이지 버튼은 대학명 헤더 우측에 배치한다.
- 주소와 Google 지도 이동은 상세 정보 영역에 제공한다.
- `admissionGuidePdf`는 PDF만 허용한다.
- `kind: dormitory`는 본문 뒤 `dormitoryPhotos[]` 캐러셀을 렌더링한다.
- 프로토타입은 고정 fixture를 사용한다. 학교 화면의 브라우저 상태를 공개 화면이 실시간 소비하지 않는다.

## 3. 조직·권한

```text
UniversityOrganization
├─ universityId
├─ topOwnerId
└─ affiliations[]
   ├─ affiliationId
   ├─ managerIds[]
   └─ memberIds[]
```

- `topOwnerId`는 정확히 1명이다.
- `managerIds[]`, `memberIds[]`는 복수다.
- 같은 사용자 ID가 여러 소속구분 배열에 포함될 수 있다.

## 4. 상담 채널

```text
ConsultationChannel
├─ studentId
├─ universityId
├─ affiliationId
├─ status: waiting | active | ended
├─ blocked: boolean
├─ blockReasonCode: advertising | abuse | other
├─ blockReasonDetail
├─ unblockReason
├─ reopenedAt
└─ messages[]
```

- `other`일 때만 `blockReasonDetail`이 필수다.
- 차단과 해제는 같은 소속구분 채널에만 적용한다.
- 학교 재개 시 학생에게 시스템 메시지를 추가한다.
- 웰컴 메시지는 최초 상담 시작 뒤에만 표시한다. 공개 대학 상세에는 표시하지 않는다.

## 5. 문서 요청·전달

```text
ConsultationDocumentRequest
├─ requestId
├─ studentId
├─ universityId
├─ affiliationId
├─ documentType
├─ status: requested | awaiting_confirmation | sent | re_requested | updated
├─ exampleFileMetadata
└─ sentDocumentMetadata
```

- 학교 요청만으로 문서 접근 권한이 생기지 않는다.
- `sent` 또는 `updated`는 학생의 명시적 확인 뒤에만 설정한다.
- 원본 파일 내용과 메시지 본문은 분석 이벤트에 포함하지 않는다.

## 6. 플랫폼 공지

```text
PlatformNotice
├─ id
├─ title
├─ summary
├─ body
├─ audience: all | student | university
├─ status: draft | published | hidden
├─ important
├─ author
├─ publishedAt
└─ updatedAt
```

- `published`만 자기 대상에게 표시한다.
- `important=true`는 목록 최상단에 표시한다.
- 학생은 GNB·햄버거, 학교는 홈 위젯·전체 보기에서 소비한다.

## 7. 분석 이벤트 금지 데이터

- 학생 이름·이메일 등 직접 식별정보
- 상담 메시지 본문
- 학생 문서명·원본·URL
- 요청 예시 파일 권한 URL
- 차단 상세 사유 전문

분석에는 `universityId`, `affiliationId`, 상태 코드, 화면·행동 이름만 사용한다.
