# 학교 스쿼드 개발 브리프

- 우선순위: P1
- 소유 경험: 대학 상담 운영, 조직·멤버, 공개정보 입력·직접 게시
- 주요 소유 파일: `university-admin.html`, 학교 프로토타입 자산

## 구현 요구사항

1. 대학 최고관리자는 대학당 정확히 1명으로 유지한다.
2. 소속구분 관리자와 멤버는 여러 소속구분에 중복 배정할 수 있다.
3. 한 소속구분에 복수 관리자·복수 멤버를 둘 수 있다.
4. 최고관리자는 전체, 관리자·멤버는 배정 범위의 공개정보·자산을 직접 게시할 수 있다.
5. 대학 운영은 단일 화면을 유지하고 권한에 따라 소속구분·상담을 필터링한다.
6. 플랫폼 어드민 공개정보 승인 단계를 만들지 않는다.
7. `입학 안내 자료`는 PDF만 허용한다.
8. 상세 탭의 추가·수정·순서·활성·비활성을 제공한다.
9. 기본 탭은 `상세 소개·학과 정보·지원 과정·기숙사`다.
10. 기숙사 편집에서 본문과 사진을 함께 관리한다.
11. 소속구분별 공식 홈페이지 HTTPS URL과 지도 검색 기준 주소를 관리한다.
12. 종료 상담을 학교가 다시 시작하고 학생에게 재개 이벤트를 전달한다.
13. 차단 사유는 `광고성 채팅·어뷰징 유저·기타` 선택형으로 제공한다. `기타`만 직접 입력을 필수화한다.
14. 모든 구성원이 배정 범위에서 차단할 수 있다. 차단 해제는 해제 사유를 필수 입력한다.
15. 학교는 문서를 요청·재요청할 수 있지만 요청만으로 학생 문서를 열람하지 못한다.
16. 학생 재전송 뒤 우측 패널에 `업데이트됨`과 빨간 점을 표시한다.
17. 학교 홈에 캘린더·To-do·플랫폼 공지 위젯을 데스크톱 3열, 중간 2열, 모바일 1열로 제공한다.
18. 구미대학교 공개 화면용 데이터는 고정 더미로 관리한다. 공개 화면 저장소 동기화 기능을 추가하지 않는다.

## 비범위

- 플랫폼 대학 등록 승인
- 플랫폼 공지 작성
- 학생 문서 보관함 전체 열람
- 메인 대학 카드·상세 렌더링 파일 수정
- 실제 서버 파일 업로드·권한 API

## 수용 기준

- 두 소속구분에 배정된 관리자가 두 상담 영역을 모두 볼 수 있다.
- 단일 소속구분 멤버는 다른 소속구분 상담·문서를 볼 수 없다.
- 멤버도 배정 범위 공개정보를 직접 게시할 수 있다.
- PDF가 아닌 입학 안내 자료를 거부한다.
- 차단·해제·재개가 해당 소속구분에만 적용된다.
- 요청하지 않았거나 학생이 보내지 않은 문서는 보이지 않는다.
- 재업로드 뒤 업데이트 표시가 정확한 문서에 연결된다.
