# 학생 스쿼드 개발 브리프

- 우선순위: P1
- 소유 경험: 학생 인증, 내 상담, 채팅, 문서 보관함, 마이페이지
- 주요 소유 파일: `login.html`, `signup.html`, `student-desktop.html`, `student-mobile.html`, `student-session.js`, `student-university-directory.js`

## 구현 요구사항

1. 메인 기준 로그인 학생 GNB와 프로필 메뉴를 동일하게 적용한다.
2. 모든 로고를 `index.html`로 연결한다.
3. 로그인 학생에게 `학교 서비스·로그인/회원가입`을 숨긴다.
4. 프로필 메뉴는 이름·이메일, `문서 보관함·마이페이지·로그아웃`만 제공한다.
5. 모바일은 햄버거 하나에 페이지 메뉴·프로필 요약·개인 메뉴·언어 선택을 제공한다.
6. 상담 목록과 이력을 `studentId + universityId + affiliationId`별로 분리한다.
7. 최초 상담에 대학 웰컴 메시지를 표시한다.
8. 종료 상담을 학교가 재개하면 재개 시스템 메시지를 표시한다.
9. 해당 소속구분에서 차단되면 재상담을 막고, 해제 뒤 해당 소속구분만 재상담을 허용한다.
10. 문서 사용자 표기 `아포스티유`를 `공증문서`로 바꾼다. 내부 `apostille` 값은 유지할 수 있다.
11. 문서 요청에 일치 등록 문서가 있으면 선택, 없으면 PDF 업로드를 제공한다.
12. 모든 전송 전에 미리보기와 `이 문서 전송` 확인을 제공한다.
13. 학교 재요청 시 업로드 상자와 기존 문서 선택을 다시 표시한다.
14. 공지사항은 데스크톱 GNB와 모바일 햄버거에서 진입한다. 프로필 메뉴에는 넣지 않는다.

## 비범위

- 대학 공개정보 편집
- 학교 구성원 권한 관리
- 공지 작성·게시
- 학생 문서의 플랫폼 어드민 열람
- 실제 파일 저장·변환·바이러스 검사

## 수용 기준

- 같은 대학의 학부와 언어교육원 상담이 별도 항목·별도 이력으로 보인다.
- 로그인 전 선택한 `universityId + affiliationId`가 가입·로그인 뒤 유지된다.
- 확인 전 문서가 전송되지 않는다.
- 취소·닫기 시 요청 상태와 문서가 유지된다.
- 재요청 뒤 새 전송이 기존 소속구분 채널에 연결된다.
- 프로필 메뉴에 `내 상담·공지사항`이 중복되지 않는다.
- 모바일 햄버거, Escape, 바깥 클릭, 로그아웃 복원을 검증한다.
