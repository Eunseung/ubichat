# 어드민 스쿼드 개발 브리프

- 우선순위: P1
- 소유 경험: 대학 등록 승인, 계정, 플랫폼 공지, 콘텐츠 CMS, 광고 구좌, 활동 이력
- 주요 소유 파일: `platform-admin.html`, `audit-log-data.js`, `notice-data.js`, `ad-slot-data.js`

## 구현 요구사항

1. 대학 등록 신청을 승인·보완·반려한다.
2. 최고관리자·소속구분 관리자·멤버 대학계정을 모두 발급할 수 있다.
3. 대학계정 활성·일시정지 등 플랫폼 계정 상태를 관리한다.
4. 학교 공개정보·로고·배경·사진·브로셔 승인 큐를 만들지 않는다.
5. 프로토타입의 현재 대학 전체 공개 상태는 읽기 전용으로 표시한다.
6. 학생·학교 전체, 학생, 학교 대상으로 플랫폼 공지를 작성·수정·게시·종료한다.
7. 중요 공지와 `draft·published·hidden` 상태를 관리한다.
8. 콘텐츠 CMS의 초안·검토·예약·게시·비공개 상태와 첨부를 관리한다.
9. 대학 광고와 기업 광고 구좌를 분리하고 활성 상태·소재·순서를 관리한다.
10. 활동 이력에는 처리자·시각·대상·작업·사유를 기록한다.
11. 학생 상담 원문·문서 원본·예시 파일 권한 URL을 열람하거나 활동 이력에 저장하지 않는다.
12. 문서 요청 예시 파일의 메타데이터·권한 URL·운영 수명주기는 플랫폼 운영 범위로 둔다.

## 비범위

- 학교 공개정보 사전 승인·수정
- 학생 상담 응대
- 학생 문서 원본 열람
- 공개 대학 상세 렌더링
- 학교 운영 화면과 공개 화면 실시간 동기화

## 수용 기준

- 대학 등록 승인과 공개정보 게시 상태를 혼동하지 않는다.
- 모든 대학 역할 계정 발급 경로가 존재한다.
- 공지는 `published`인 자기 대상에게만 표시된다.
- 종료 공지는 삭제하지 않고 `hidden`으로 전환한다.
- 비활성 광고와 미게시 콘텐츠가 공개 화면에 노출되지 않는다.
- 활동 이력에 상담 원문·학생 문서 정보가 포함되지 않는다.
- 데스크톱·모바일 관리자 화면과 JavaScript 문법을 검증한다.
