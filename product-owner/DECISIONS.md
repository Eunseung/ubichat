## D-008 — 대학 조직 권한과 공개정보 게시 권한

- 날짜: 2026-07-28
- 상태: 확정
- 결정:
  1. 대학별 최고관리자(오너)는 정확히 1명이다. 운영사가 별도 발급하거나 최초 대학 등록 신청 때 발급한다.
  2. 소속구분 관리자는 하나 이상의 소속구분을 동시에 맡을 수 있다. 운영사 또는 최고관리자가 발급한다. 예: 한국대학교 학부/학사 관리자와 언어교육원 관리자를 같은 계정으로 맡을 수 있다.
  3. 멤버는 하나 이상의 소속구분에 배정될 수 있다. 운영사, 소속구분 관리자 또는 최고관리자가 발급한다.
  4. 최고관리자는 대학 전체와 모든 소속구분을 관리한다. 소속구분 관리자와 멤버의 기본 업무 범위는 배정된 모든 소속구분이다.
  5. 어드민은 대학 등록을 승인하며, 최고관리자·소속구분 관리자·멤버 대학계정을 발급할 수 있다. 등록 후 대학 공개정보·로고·배경·사진·브로셔의 입력·변경·게시에는 어드민 사전 승인이 없다.
  6. 최고관리자·소속구분 관리자·멤버 모두 배정된 소속구분의 공개정보와 자산을 직접 게시할 수 있다. 최고관리자는 모든 소속구분에 이 권한을 가진다.
- 배경: 대학 내부 조직과 실제 입학 업무 단위를 반영하고, 등록 완료 대학의 정보 운영 속도를 확보한다.
- 근거: 사용자 제공 권한 정책, 제품 원칙 4·6·7·9
- 영향받는 스쿼드: 학교, 어드민, 메인·탐색·콘텐츠, 학생
- 관련 KPI: 대학 등록 처리 시간, 공개정보 게시 완료율, 상담 수신 대학 비율, 권한 오류 건수
- 후속 작업: 학교 스쿼드는 복수 소속구분 배정과 역할별 직접 게시 권한을 명세한다. 어드민은 대학 등록과 모든 대학계정 발급·플랫폼 계정 상태를 설계한다. 공통 공개정보 계약은 `profileDraft` 승인 흐름을 직접 게시 흐름으로 전환한다.

## D-011 — 채팅 목록의 학생 차단

- 날짜: 2026-07-28
- 상태: 확정
- 결정:
  1. 학생 차단은 채팅 목록에서 실행한다. 최고관리자·소속구분 관리자·멤버 등 모든 대학 구성원이 배정된 소속구분 범위에서 실행할 수 있다. 차단된 학생은 해당 대학에 재상담할 수 없다.
  2. 차단 해제도 채팅 목록에서 실행한다. 차단 권한이 있는 대학 구성원은 해제 사유를 반드시 입력해야 하며, 해제 뒤 학생은 해당 대학에 다시 상담할 수 있다.
- 배경: 대학 상담 운영자가 채팅 목록에서 즉시 상담 접근을 통제한다.
- 근거: 노션의 채팅 목록 차단 요구와 사용자 확인
- 영향받는 스쿼드: 학교, 학생, 어드민
- 관련 KPI: 차단·차단 해제 후 상담 접근 제어 성공률, 권한 오류 건수, 사유 포함 감사 로그 누락 건수
- 후속 작업: 학교 스쿼드는 채팅 목록 차단·사유 필수 해제 동작을, 학생 스쿼드는 차단·해제 뒤 재상담 가능 상태를, 어드민 스쿼드는 행위자·시각·대상·사유를 포함한 차단·해제 이력을 명세한다.
- 대체 대상: 없음

## D-013 — 소속구분별 대학 공개 카드와 단일 상담 채널

- 날짜: 2026-07-29
- 상태: 확정
- 결정:
  1. 학생 탐색의 노출 단위는 대학이 아니라 `대학 + 공개 소속구분`이다. 공개된 소속구분마다 카드 1개를 만든다. 예: 서정대학교의 학부/학사·언어교육원·대학원이 공개되면 `서정대학교`, `서정대학교 언어교육원`, `서정대학교 대학원` 카드 3개를 노출한다.
  2. 카드와 상세는 대학 및 해당 소속구분이 모두 `published`일 때만 노출한다. 카드명은 해당 소속구분의 공개 표시명을 사용한다.
  3. 카드는 선택된 `affiliationId`를 유지한 상세로 연결한다. 상세에는 선택 소속구분의 공개 정보와 자산만 표시하며, 자산·필드가 없을 때는 깨지지 않는 기본·빈 상태를 사용한다.
  4. 학생과 대학 사이의 상담 채널은 대학당 하나로 유지한다. 카드에서 시작한 상담은 선택 소속구분을 그 채널의 상담 맥락으로 저장할 뿐, 별도 상담 채널이나 별도 대학 운영 페이지를 만들지 않는다.
  5. 대학 운영은 기존 단일 화면을 유지하며, 역할자가 배정된 소속구분의 상담·정보를 그 화면에서 관리한다. 웰컴 메시지·이미지는 상담 시작 뒤에만 표시하고 공개 상세에는 노출하지 않는다.
- 배경: 학생은 실제 상담·지원 단위를 명확히 인지하고, 대학은 한 운영 화면과 하나의 학생 상담 관계를 유지한다.
- 근거: 사용자 제공 서정대학교 3개 공개 카드 예시 및 기존 단일 운영 화면 정책
- 영향받는 스쿼드: 메인·탐색·콘텐츠, 학교, 학생
- 관련 KPI: 소속구분별 카드 노출률, 카드→상세 진입률, 상세→상담 시작률, 소속구분 맥락 누락률
- 후속 작업: 메인은 카드·상세·CTA를 소속구분 맥락으로 구현한다. 학교는 소속구분별 공개 데이터를 생산한다. 학생은 동일 대학 상담 채널에 `affiliationId` 맥락을 보존한다. 공통 계약 본문은 CR 필수 검토 후 변경한다.
- 대체 대상: CR-2026-07-29의 기본 소속구분·공개 조건·웰컴 메시지 관련 미결 요청
- 사용자 최종 확인: 2026-07-29

## D-012 — 중요 정책·모호한 요청의 사용자 확인 게이트

- 근거: 사용자 직접 지시
- 영향받는 스쿼드: Product Owner, 학생, 학교, 어드민, 메인·탐색·콘텐츠
- 관련 문서: `shared/USER_CONFIRMATION_POLICY.md`, 모든 `AGENTS.md`, 역할 에이전트 문서

  3. 학생은 GNB를 늘리지 않고 프로필 메뉴의 `공지사항`에서 전체 목록과 본문을 확인한다. `student-mobile.html`은 통합 반응형 학생 화면으로 이동하므로 같은 메뉴·페이지를 사용한다.
  4. 학교는 홈의 운영 도구 영역에서 캘린더·To-do·공지사항을 함께 본다. 넓은 데스크톱은 3열, 중간 폭은 2열, 모바일은 1열로 배치한다. `전체 보기`에서 목록과 본문을 확인한다.
  5. 중요 공지는 대상 목록의 최상단에 표시한다. 종료는 삭제가 아니라 `hidden` 상태 전환이다.
- 배경: 학생·학교가 서비스 운영 변경과 필수 안내를 로그인 뒤 놓치지 않고 확인해야 한다.
- 근거: 사용자 직접 확인 및 배치 지시 (2026-07-29)
- 영향받는 스쿼드: 학생, 학교, 어드민
- 관련 문서·KPI: `shared/contracts/platform-notices.md`, 공지 대상별 게시 도달률, 중요 공지 열람률
- 후속 작업: 어드민은 공지 관리 화면과 공통 데이터를 소유한다. 학생은 프로필 메뉴·반응형 공지 페이지를, 학교는 홈 위젯·전체 보기 페이지를 유지한다. 사용자 화면 검수 전 구현 완료로 종료하지 않는다.
- 대체 대상: 없음

## D-021 — 로그인 학생 GNB와 모바일 통합 메뉴

- 날짜: 2026-07-29
- 상태: 확정
- 결정:
  1. 학생 로그인 상태의 공개·학생 GNB에서 `학교 서비스` 또는 `대학 서비스`를 숨긴다. 로그아웃 상태에는 기존 진입점을 유지한다.
  2. 데스크톱은 `대학 탐색·내 상담·콘텐츠`, 별도 프로필 메뉴, 별도 언어 선택을 유지한다.
  3. 축소 화면은 햄버거 메뉴 하나에 페이지 메뉴, 학생 이름·이메일, `공지사항·문서 보관함·마이페이지·로그아웃`, 언어 선택을 순서대로 넣는다. 프로필 버튼과 언어 버튼을 햄버거 밖에 중복 표시하지 않는다.
  4. 메인 스쿼드는 공통 GNB 구조·반응형 표현을, 학생 스쿼드는 로그인 상태·프로필 정보·개인 목적지를 제공한다.
- 배경: 로그인 학생에게 학교 운영자 진입점이 노출되고, 축소 화면에서 페이지·프로필·언어 메뉴가 분산되는 문제를 해소한다.
- 근거: 사용자 직접 지시 (2026-07-29)
- 영향받는 스쿼드: 메인·탐색·콘텐츠, 학생
- 관련 문서·KPI: `shared/contracts/navigation-auth.md`, 로그인 상태 잘못된 역할 진입점 노출 건수, 모바일 개인 메뉴 목적지 도달 성공률
- 후속 작업: 모든 공개 화면과 학생 포털에서 로그인·로그아웃 및 620px/760px 축소 상태를 함께 검증한다.
- 대체 대상: `D-024 — 메인 랜딩의 학생·학교 서비스 동시 진입`의 결정 3 및 같은 규칙을 인용한 문서. 비로그인 상태의 학생·학교 동시 진입은 유지한다.

## D-023 — 내부 보고 수정사항과 정적 HTML 배포 기준

- 날짜: 2026-07-30
- 상태: 확정
- 결정:
  1. 메인 랜딩 히어로에 대학명·지역·분야 검색을 제공한다. 검색은 `university-explore.html?q={query}`로 이동해 같은 검색어를 적용한다.
  2. 공개 GNB에 `FAQ`, `공지사항`을 추가하고 비로그인 버튼명은 `로그인/회원가입`으로 바꾼다. 공지는 GNB 진입만 공개하며, 비로그인 사용자는 로그인 뒤 자기 대상 공지 화면으로 이동한다.
  3. FAQ는 독립 `faq.html`과 랜딩의 TOPIK 안내 바로 위 미리보기로 제공한다. FAQ는 공개이며 대학·학생 계정으로 로그인하지 않아도 읽을 수 있다.
  4. 학생 문서 분류의 사용자 표기는 `아포스티유`에서 `공증문서`로 바꾼다. 기존 내부 분류값은 문서 요청 호환을 위해 유지한다. 최초 상담 시 대학 웰컴 메시지가 표시되는 별도 시나리오를 추가한다.

  6. 학교는 종료 채팅을 다시 시작할 수 있으며, 학생에게 재개 사실을 시스템 메시지로 남긴다. 차단 사유는 `광고성 채팅·어뷰징 유저·기타` 중 선택하며 `기타`만 상세 사유를 필수 입력한다.
  7. 정적 배포의 실제 메인 화면은 `index.html`이다. `기업용_배너_포함.html`은 기존 링크 호환용 진입 경로로 유지한다.

- 후속 작업: 각 스쿼드는 `INTERNAL_REVIEW_P1_2026-07-30.md`와 자기 즉시 실행 문서의 P1 항목을 먼저 수행한다. 공통 계약은 학교·메인·학생·어드민 필수 검토 뒤 반영한다.
