# 내부 보고 수정사항 P1 배정 — 2026-07-30

- 근거: D-023

## 공통 완료 조건

- 사용자 화면 표기는 `ubichat`을 사용한다.
- 데스크톱·모바일, 빈 상태·오류·권한·로그인 상태를 확인한다.
- 모든 신규 링크는 정적 HTML 상대 경로로 동작한다.
- `기업용_배너_포함.html` 기존 링크는 `index.html`과 같은 메인 경험으로 이어진다.

## 메인·탐색·콘텐츠 — P1

### PM

- 히어로 검색의 대상은 대학명·지역·분야다. Enter·검색 버튼 모두 `university-explore.html?q={query}`로 이동한다.
- 공개 GNB 순서는 `대학 탐색 · 상담하기/내 상담 · 콘텐츠 · FAQ · 공지사항`이다. 비로그인 우측 버튼은 `학교 서비스 · 로그인/회원가입`이다.
- FAQ는 공개 `faq.html`과 랜딩 TOPIK 안내 위 미리보기로 같은 문답을 제공한다.
- 공지 GNB는 비로그인에서 로그인 반환 경로를 보존하고, 로그인 학생은 자기 대상 공지로 바로 이동한다. 공지 본문을 공개 데이터로 만들지 않는다.
- `index.html`을 실제 랜딩 본문으로 전환하고 배너 포함 시안은 호환 진입으로 유지한다.

### Designer

- 히어로 검색은 큰 단일 입력창, 검색 아이콘·실행 버튼, 44px 이상 터치 영역, 명확한 placeholder·결과 없음 상태를 제공한다.
- 데스크톱·모바일 GNB에서 FAQ·공지 추가 뒤 항목이 잘리거나 중복되지 않게 한다.
- FAQ 미리보기는 3~5개 문답, 전체 보기 CTA를 제공하며 TOPIK 블록 바로 위에 둔다.

### Developer

- 소유 파일: `index.html`, `기업용_배너_포함.html`, `landing.css`, `landing.js`, 공개 GNB HTML, `university-explore.js`, `faq.html`.
- `q` 파라미터 검색, FAQ 페이지·미리보기, 공지 로그인 반환, 다국어 문구를 구현한다.
- `index.html`이 랜딩을 직접 렌더링하고 기존 배너 포함 URL이 깨지지 않게 한다.

### 인수 조건

- 검색어가 탐색 결과와 입력창에 유지됨.
- FAQ·공지·로그인/회원가입이 공개 GNB와 모바일 메뉴에서 모두 접근 가능함.
- 비로그인 공지 클릭은 로그인 뒤 학생 대상 공지로 복귀함.
- `index.html` 단독 정적 배포에서 랜딩 자산·링크·JavaScript가 동작함.

## 학생 — P1

### PM

- 문서 분류의 화면 표기만 `공증문서`로 변경한다. 기존 `apostille` 내부 값과 과거 문서는 유지한다.
- 최초 상담 시나리오는 소속구분별 대학 웰컴 메시지 1회, 학생 첫 메시지 전 표시를 완료 기준으로 둔다.
- 대학이 종료 채팅을 재개하면 학생은 시스템 메시지와 재개된 입력 상태를 확인한다. 학생이 직접 재문의한 경우와 구분한다.

### Designer

- 문서함·업로드·기존 문서 선택·요청 카테고리의 `공증문서` 표기를 일관되게 적용한다.
- 최초 채팅 시나리오는 웰컴 메시지, 작성 가능 입력창, 시간·발신자 구분을 보여 준다.
- 대학 재개 메시지는 일반 채팅과 구분되지만 경고처럼 보이지 않게 한다.

### Developer

- 소유 파일: `student-desktop.html`, `student-mobile.html`, `student-session.js`.
- 사용자 표기 매핑만 바꾸고 기존 문서 데이터·전송 요청 키를 깨지 않는다.
- 최초 웰컴 시나리오와 학교 재개 이벤트를 소속구분 채널별로 렌더링한다.

### 인수 조건

- 학생 화면 어디에도 문서 분류명 `아포스티유`가 보이지 않음.
- 최초 상담과 대학 재개 시 학생이 각각 다른 시스템 상태를 확인하고 바로 대화할 수 있음.

## 학교 — P1

### PM

- `입학 안내 자료`는 파일 형식 PDF만 허용한다. 잘못된 형식·빈 파일·용량 오류를 정의한다.
- 공개 상세 탭은 기본 5개와 추가 탭을 지원한다. 각 탭은 제목·본문·순서·활성 상태를 가진다. 비활성 탭은 공개 상세에 노출하지 않는다.
- 기숙사 사진은 별도 `기숙사 사진` 탭에서 캐러셀로 제공한다.
- 종료 채팅 재개는 배정된 소속구분 관계자만 실행한다. 재개 시 학생에게 시스템 메시지를 전송하고 채팅 상태를 진행 중으로 바꾼다.
- 차단 사유는 `광고성 채팅·어뷰징 유저·기타`; `기타`일 때만 직접 입력을 요구한다.

### Designer

- PDF 업로드 제약·오류·기존 파일 교체 상태를 학교 소개글 작성 화면에 제공한다.
- 탭 편집은 추가·수정·순서·활성 토글·삭제 확인을 제공한다. 기숙사 사진 탭은 사진 없음·1장·복수 사진 캐러셀 상태를 포함한다.
- 채팅 종료 상태에 `다시 시작`을, 차단 모달에 사유 선택과 조건부 상세 입력을 배치한다.

### Developer

- 소유 파일: `university-admin.html`, `university-data.js`, `shared/contracts/university-publication.md` 초안.
- PDF MIME·확장자 검증, 공개 탭 데이터, 활성 상태·기숙사 사진 목록, 채팅 재개 시스템 이벤트, 차단 사유 enum·조건부 상세 입력을 구현한다.
- 메인·학생 소비자에게 공개 탭 및 상담 재개 상태를 인계한다.

### 인수 조건

- 입학 안내 자료는 PDF 외 업로드 불가.
- 활성 탭만 공개 상세에 순서대로 표시되고 기숙사 사진은 캐러셀로 동작함.
- 종료 채팅 재개 뒤 학생과 학교가 같은 진행 상태·시스템 메시지를 봄.
- 차단 사유는 선택 필수, `기타` 상세 사유만 필수임.
