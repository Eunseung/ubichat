# P1 소속구분별 대학 탐색·상세 명세

- 상태: 프로토타입 구현 완료 — 공개 계약 연동 대기
- 승인 근거: 사용자 P1 시작 지시, D-008, D-013
- 범위: 메인·탐색·콘텐츠 공개 경험

## 목표

유학 준비 학생이 대학의 실제 상담·지원 단위인 공개 소속구분을 탐색하고, 선택 소속구분의 독립 상담 채널로 이동한다.

## 공개 데이터 경계

- 프로토타입은 `university-public-prototype.js`의 더미 소속구분만 읽는다. 학교 운영 화면 상태는 읽지 않는다.
- D-017에 따라 프로토타입의 현재 대학은 모두 공개한다. 소속구분 더미가 없는 대학에는 `undergraduate` 기본 소속구분 카드 1개를 사용한다. 이는 실서비스 계약에 넣지 않는다.
- 공개 계약 확정 뒤에는 학교가 계약 데이터에 직접 게시한 정보만 읽는다.
- 대학과 해당 소속구분의 `publication.status`가 모두 `published`일 때만 공개한다.
- 학교 내부 입력 화면 상태, 웰컴 메시지·이미지, 멤버·학생 정보는 읽거나 노출하지 않는다.
- 자산·필드를 대학 공통 값으로 자동 복제하거나 공개 상태를 보정하지 않는다.
- 공통 계약 본문은 이 문서로 변경하지 않는다.

## IA와 문구

### 대학 탐색

- 카드 단위: `universityId + affiliationId`
- 카드명: 소속구분의 공개 표시명. 예: `서정대학교`, `서정대학교 언어교육원`, `서정대학교 대학원`
- 카드 링크: `university-detail.html?universityId={universityId}&affiliationId={affiliationId}`
- 카드 보조 정보: 지역, 공개된 분야, 선택 소속구분의 상담 상태·응답 안내만 표시한다.
- 결과 없음: `공개된 대학 정보가 아직 없습니다. 다른 조건으로 다시 찾아보세요.`

### 대학 상세

- 제목·한 줄 소개·본문·학과/지원 과정·기숙사/장학금·사진·브로셔·상담 상태는 선택한 소속구분 값만 표시한다.
- 1차 출시에는 상세 내 소속구분 전환을 제공하지 않는다.
- 로고 없음: 대학 이니셜 기본 이미지.
- 히어로·사진 없음: 기본 배경 또는 `등록된 소개 사진이 없습니다.`
- 본문/과정/혜택/브로셔 없음: 각 영역에 `등록된 정보가 없습니다.`
- 브로셔는 유효한 공개 링크가 있을 때만 `보기`를 제공한다. 링크가 없으면 비활성 상태와 안내를 표시한다.
- 공개되지 않았거나 존재하지 않는 `affiliationId`: 상세를 렌더링하지 않고 탐색으로 안전하게 돌아간다.

### 상담 CTA

- 문구: `상담 시작하기`
- 로그인: `student-desktop.html?universityId={universityId}&affiliationId={affiliationId}`
- 비로그인: 로그인 후 위 목적지로 돌아오도록 `returnTo`와 두 식별자를 모두 전달한다.
- 상담 채널은 `studentId + universityId + affiliationId`별로 독립한다. 메인은 `universityId`, `affiliationId`를 학생 화면으로 전달만 하며, 별도 대학 운영 화면을 만들지 않는다.
- 선택 소속구분의 상담 상태가 신규 상담 불가면 CTA를 비활성화하고 해당 상태 안내만 표시한다.

## 반응형·접근성

- 데스크톱: 카드 그리드, 상세 정보와 상담 CTA를 분리해 표시한다.
- 모바일: 카드 1열, 상세 CTA를 정보 앞에 배치한다.
- 카드·브로셔·CTA는 키보드 포커스와 명확한 이름을 가진다.
- 이미지 대체 텍스트는 소속구분 공개 표시명과 자산 용도를 사용한다.
- 상태는 색만으로 구분하지 않는다.

## 수용 기준

1. Given 대학과 세 소속구분이 모두 공개됨, When 탐색을 열면, Then 세 `universityId + affiliationId` 카드가 각각 표시된다.
2. Given 대학 또는 소속구분이 비공개임, When 탐색·상세를 열면, Then 해당 소속구분은 노출되지 않는다.
3. Given 카드를 선택함, When 상세와 상담 CTA로 이동하면, Then 동일한 `affiliationId`가 URL과 상담 전달값에 유지된다.
4. Given 선택 소속구분의 자산·필드가 비어 있음, When 상세를 열면, Then 대학 공통 자산을 복제하지 않고 안전한 기본·빈 상태를 표시한다.
5. Given 공개 상세를 열음, When 화면을 확인하면, Then 웰컴 메시지·웰컴 이미지는 표시되지 않는다.
6. Given 학생 로그인 상태임, When 공개 GNB를 열면, Then `학교 서비스`는 숨겨지고 `학생 로그인`은 프로필 메뉴로 전환되며 `내 상담`에 진입할 수 있다. 축소 화면에서는 페이지·프로필·다국어 메뉴가 하나의 햄버거에 표시된다.
7. Given 프로토타입의 현재 대학, When 탐색을 열면, Then 모든 대학이 최소 1개 카드로 표시되고 구미대학교는 3개 소속구분 카드로 표시된다.

## 분석 이벤트 초안

공통 이벤트 계약 검토 전까지 구현하지 않는다. 공통 속성 외 허용 속성은 `universityId`, `affiliationId`, `authState`, `sourcePage`, `deviceType`뿐이다.

| 이벤트 | 시점 | 목적 |
| --- | --- | --- |
| `discovery.affiliation.card_impression` | 카드가 화면에 표시될 때 | 소속구분별 카드 노출 |
| `discovery.affiliation.detail_view` | 유효한 상세가 열릴 때 | 카드→상세 전환 |
| `discovery.affiliation.consultation_cta_click` | 상담 CTA를 누를 때 | 상세→상담 의도 |

이벤트에 학생 식별자·연락처·문서명·문서 URL·메시지 본문을 넣지 않는다.

## 보류 — 학생 유치 홍보 페이지

D-010에 따라 학생 유치 홍보 페이지와 `등록 문의` 흐름은 보류한다. 기존 산출물은 보존하며, 사용자 재개 지시 전에는 화면·문의 흐름·분석 이벤트를 설계하거나 구현하지 않는다.

## 인계

- 학교: 소속구분별 공개 계약 데이터와 `published` 상태를 생산한다.
- 학생: 인증·가입 반환 뒤에도 `universityId + affiliationId`별 독립 상담 채널·목록을 유지한다. [인계 요청](../../shared/change-requests/CR-2026-07-29-affiliation-consultation-channel-alignment.md)
- Product Owner: 분석 이벤트 계약을 확정한다. 홍보 문의 처리 주체·완료 정의는 D-010 보류를 유지한다.
