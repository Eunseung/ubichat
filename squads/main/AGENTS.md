# 메인·탐색·콘텐츠 스쿼드 세션 지침

이 세션은 공개 서비스 경험을 담당한다. 루트 `AGENTS.md`와 이 문서를 먼저 읽는다.

## 역할 선택

- 제품 목표, 공개 범위, 콘텐츠 유형, 탐색 정책, 수용 기준: `PRODUCT_MANAGER.md`
- GNB, 랜딩, 탐색·상세, 콘텐츠·광고 UI, 반응형·접근성: `DESIGNER.md`
- HTML/CSS/JavaScript, 데이터 소비, 라우팅, 이벤트, 검증: `DEVELOPER.md`

복합 기능은 Product Manager → Designer → Developer 순서로 진행한다.

## 스쿼드 경계

담당:

- 공개 랜딩·GNB
- 대학 탐색·상세 렌더링
- 콘텐츠 탐색·소비 경험
- 광고 노출 위치·형태
- 공개 화면의 분석 이벤트

비담당:

- 학생 상담·문서·프로필 내부 기능
- 대학 상담 인박스와 멤버 관리
- 대학 승인·계정·감사
- 콘텐츠 CMS와 광고 구좌 운영

## 협업 규칙

- 로그인 상태와 `내 상담` 목적지는 학생 스쿼드 계약을 사용한다.
- 대학 공개정보는 대학 등록 승인 뒤 학교 스쿼드가 직접 게시한 데이터만 표시한다. 어드민의 공개정보·자산 사전 승인은 없다.
- 콘텐츠와 광고는 어드민의 게시·활성 상태를 변경하지 않고 소비한다.
- `university-data.js`, `ad-slot-data.js`, `unichat-brand.css` 변경 전 `shared/FILE_OWNERSHIP.md`를 확인한다.
- 공통 계약 변경은 `shared/change-requests/`에 기록한다.

## 세션 시작

1. 요청이 공개 경험 범위인지 확인
2. 필요한 역할 문서 읽기
3. 관련 Product Owner 결정 확인
4. 영향받는 학생·학교·어드민 계약 확인
5. 산출물과 검증 방법 선언

## 사용자 확인 게이트

`shared/USER_CONFIRMATION_POLICY.md`를 따른다. GNB, 공개 범위, 광고·콘텐츠 정책, 로그인 게이팅, 분석 계약 또는 모호한 요청은 사용자 승인 전 수정·구현하지 않는다. 완료 후 결과 확인도 받는다.
