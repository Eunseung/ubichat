# 메인·탐색·콘텐츠 스쿼드 즉시 실행 — 2026-07-29

- 상태: 사용자 확정 정책 반영, P1 실행
- D-025 메인 기준 로그인 학생 GNB·모바일 통합 메뉴: 구현 완료 보고, 학생 정합화·공동 화면 검수 대기
- 근거: D-010(보류), D-014, D-015, D-017, D-018, D-019, D-021
- 담당: 메인 PM → Designer → Developer

## 1. GNB 정합성

- 공개·학생 인증 화면의 로고는 모두 `index.html`로 이동한다.
- 비로그인: `대학 탐색 · 상담하기 · 콘텐츠 · FAQ · 공지사항`. 우측에는 `학교 서비스`와 `로그인/회원가입`을 표시한다.
- 로그인 학생: `학교 서비스`와 `로그인/회원가입`을 숨기고 `대학 탐색 · 내 상담 · 콘텐츠 · FAQ · 공지사항`과 프로필 메뉴를 제공한다.
- 로그인 학생 프로필 메뉴: 학생 이름·이메일, `문서 보관함 · 마이페이지 · 로그아웃`만 제공한다. `내 상담 · 공지사항`을 중복하지 않는다.
- 620px 이하: 햄버거에 `대학 탐색 · 내 상담 · 콘텐츠 · FAQ · 공지사항`, 학생 이름·이메일, `문서 보관함 · 마이페이지 · 로그아웃`, 언어 선택을 통합한다. 프로필·언어 선택을 햄버거 밖에 중복 표시하지 않는다.
- 학생 스쿼드의 760px 이하 학생 포털과 같은 목적지·순서·상태인지 확인한다.

## 2. 소속구분 공개 카드·상세

- 카드 단위는 `universityId + affiliationId`다. 예: `서정대학교`, `서정대학교 언어교육원`, `서정대학교 대학원`.
- 대학과 선택 소속구분이 모두 `published`일 때만 카드·상세를 노출한다.
- 카드 → 상세 → 상담 CTA까지 두 값을 유지한다.
- CTA는 학생의 `studentId + universityId + affiliationId` 독립 상담 채널로 연결한다. 메인은 별도 대학 운영 화면을 만들지 않는다.
- 선택 소속구분의 공개정보·자산만 표시하고 빈 값은 안전한 기본·빈 상태로 처리한다.
- D-017 프로토타입에서는 현재 대학을 모두 공개한다. 소속구분 더미가 없는 대학은 `undergraduate` 기본 카드 1개를 만들고, 구미대학교의 3개 소속구분 카드는 유지한다.

## 3. 대기·제외

- `university-publication` v2 확정 전 학교 내부 화면 상태를 직접 읽지 않는다. `undergraduate` 기본 카드는 프로토타입 전용이며 공통 계약에 넣지 않는다.
- 학생 유치 홍보 페이지와 `등록 문의`는 D-010 보류다. 기존 산출물은 보존하고 신규 화면·이벤트를 만들지 않는다.
- 학생 서류 요청·업로드·전달은 학생·학교 범위이므로 메인 화면을 만들지 않는다.
- D-018의 수신 문서 재요청·재업로드·업데이트 표시는 학생·학교 범위다. 메인은 문서 원본·상태를 탐색·상세에 노출하지 않는다.

## 4. 내부 보고 수정사항·정적 배포 — D-023

- 상태: P1 실행
- PM: 히어로 검색은 대학명·지역·분야를 `university-explore.html?q={query}`로 연결한다. 공개 GNB에 `FAQ·공지사항`을 추가하고 비로그인 버튼을 `로그인/회원가입`으로 바꾼다. 공지 GNB는 로그인 반환만 제공하며 공지 본문을 공개하지 않는다.
- Designer: 히어로 검색, 데스크톱·모바일 GNB, TOPIK 바로 위 FAQ 미리보기와 공개 `faq.html`의 목록·본문·빈 상태를 설계한다.
- Developer: `index.html`을 직접 렌더링하는 정적 메인 랜딩으로 전환한다. 기존 `기업용_배너_포함.html`은 호환 진입으로 유지한다. 검색 쿼리·FAQ·공지 로그인 반환·다국어 문구를 구현한다.
- 공개 상세 소비자: 학교가 생산한 활성 공개 탭만 순서대로 렌더링하고, `기숙사 사진` 탭은 사진 캐러셀로 표시한다.
- 수용 기준: `index.html` 단독 배포에서 랜딩·자산·링크·JavaScript가 동작함; 검색어가 탐색 URL·결과에 유지됨; FAQ·공지·로그인/회원가입이 GNB와 모바일 메뉴에 있음; 비로그인 공지 클릭은 로그인 뒤 대상 공지로 복귀함.

## 5. 메인 기준 GNB 정합화 — D-025

- 상태: 메인 구현 완료 보고, 학생 스쿼드 반영·공동 화면 검수 대기
- 기준: 로그인 학생의 데스크톱 GNB는 `대학 탐색·내 상담·콘텐츠·FAQ·공지사항`이다. 프로필 메뉴는 이름·이메일, `문서 보관함·마이페이지·로그아웃`만 제공한다.
- 발견 결함: `index.html` 프로필 메뉴에 `내 상담` 정적 링크가 남아 있다. `public-navigation.js`의 런타임 제거는 `data-student-context` 링크만 대상으로 하므로 이 정적 링크를 제거하지 못한다.
- Developer: `index.html`의 정적 `내 상담` 링크를 제거한다. `public-navigation.js`의 런타임 삭제에 의존하지 않고, 정적 프로필 메뉴 자체가 `문서 보관함·마이페이지·로그아웃`만 갖게 한다. 로그인·로그아웃과 620px 이하 햄버거에서 `내 상담·공지사항`이 프로필 메뉴에 중복되지 않는지 회귀 검증한다. 모든 로고 목적지는 `index.html`이다.
- 공동 수용 기준: 로그인 학생 프로필 메뉴 항목은 정확히 `문서 보관함·마이페이지·로그아웃` 3개다. 학생 스쿼드 화면과 항목·순서·목적지·학교 서비스 숨김 상태가 일치한다.
