# 학생 스쿼드

학생이 ubichat에 가입하고 로그인한 뒤 자신의 상담을 안전하고 편리하게 이어가는 경험을 담당한다.

## 구성

| 역할 | 역할 문서 | 핵심 책임 |
|---|---|---|
| Product Manager | `PRODUCT_MANAGER.md` | 학생 문제, 요구사항, 정책 제안, 우선순위, 완료 기준 |
| Designer | `DESIGNER.md` | 학생 여정, 화면·상태·반응형·접근성 설계 |
| Developer | `DEVELOPER.md` | 학생 화면과 세션 로직 구현, 검증, 기술 인계 |

세션을 시작하는 AI는 먼저 `AGENTS.md`를 읽고 요청에 맞는 역할 문서를 반드시 읽는다.

## 소유 파일

- `/login.html`
- `/signup.html`
- `/student-desktop.html`
- `/student-mobile.html`
- `/student-session.js`

위 파일의 제품 품질은 학생 스쿼드가 책임진다. 기존 사용자 수정사항을 보존하고, 작업 전 변경 상태를 확인한다.

## 비소유 영역

- 공개 랜딩, 대학 찾기, 대학 상세, 콘텐츠 소비 화면: 탐색·콘텐츠 스쿼드
- GNB 구조·공통 shell·공통 내비게이션 표현: 탐색·콘텐츠 스쿼드
- 대학 운영 화면과 대학 측 상담 처리: 학교 스쿼드
- 플랫폼 운영, 승인, 광고·콘텐츠 관리: 어드민 스쿼드
- 사업 방향, 전사 정책, 스쿼드 간 우선순위: Product Owner
- 인증 상태, 대학 데이터, 상담 상태, URL, 분석 이벤트 등 공통 형식: `shared` 계약

학생 스쿼드는 비소유 파일을 직접 수정하지 않는다. 필요한 변경은 담당 스쿼드에 인계하고, 공통 계약 변경은 Product Owner 승인 절차로 보낸다.

## 핵심 경계

- `내 상담` 화면과 학생별 상담 경험은 학생 스쿼드가 소유한다.
- GNB의 `내 상담` 위치·공통 외형은 탐색·콘텐츠 스쿼드가 소유한다.
- 학생의 로그인 상태와 학생 전용 링크에 필요한 값은 승인된 `shared` 계약으로 제공한다.
- 대학 공개 정보의 표시 방식과 탐색 UX는 탐색·콘텐츠 스쿼드가 소유한다.
- 대학이 입력하는 데이터와 상담 응대 동작은 학교 스쿼드가 소유한다.
- 상담 종료 권한처럼 양측 흐름에 영향을 주는 정책은 학생 스쿼드가 단독 확정하지 않는다.

## 기본 작업 흐름

1. Product Owner의 방향과 최신 결정을 확인한다.
2. Product Manager가 문제, 범위, 비범위, 의존성, 완료 기준을 확정한다.
3. Designer가 전체 상태와 반응형 동작을 설계한다.
4. Developer가 승인된 요구사항과 디자인을 구현·검증한다.
5. Product Manager가 완료 기준을 검수하고, 스쿼드 간 변경은 담당자에게 인계한다.

## 공통 인계 형식

스쿼드 밖으로 요청할 때 다음을 포함한다.

- 배경과 사용자 문제
- 요청하는 결정 또는 변경
- 영향을 받는 화면·파일·공통 계약
- 제약과 비범위
- 완료 기준
- 미결 위험과 필요한 승인자
