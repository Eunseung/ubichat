# 학생 스쿼드 즉시 실행 — 2026-07-29

- 상태: 사용자 확정 정책 반영, P1 실행
- 근거: D-009, D-015, D-016, D-017, D-018, D-021
- 담당: 학생 PM → Designer → Developer

## 1. 대학 서류 요청 응답

1. 학교가 서류를 요청하면 학생의 같은 유형 등록 문서가 있는지 확인한다.
2. 있으면 학생 추가 행동 없이 해당 소속구분 상담 채널로 즉시 전송한다.
3. 없으면 학생에게 업로드를 요청하고, PDF 1개·10MB 이하 검증 뒤 해당 요청으로 전달한다.
4. 외부 클라우드 자료는 `기타`의 HTTPS 링크만 저장·표시하며 파일을 복제하지 않는다.
5. 학교가 이미 수신한 문서를 재요청하면 같은 `studentId + universityId + affiliationId` 채널에 재업로드 상자를 다시 만든다. `업로드 하기`에서 새 PDF 업로드 또는 같은 유형의 기존 문서 선택을 제공한다.

### 수용 기준

- 등록 문서가 있으면 즉시 전송 결과를 학생이 확인한다.
- 없으면 업로드 → 전달이 하나의 흐름으로 이어진다.
- 실패·용량 초과·형식 오류·링크 접근 실패 상태를 제공한다.
- 재요청 문서는 새 PDF 업로드와 기존 문서 선택 모두로 전송할 수 있다.
- 재전송 뒤 학교 우측 패널의 문서 업데이트 알림에 필요한 채널·문서 유형·파일명만 전달한다. 문서 본문·URL은 전달하지 않는다.
- 문서명·URL·메시지 본문을 분석 이벤트에 넣지 않는다.

## 2. 소속구분별 독립 상담

- 로그인·가입 반환과 학생 상담 목록에서 `universityId`, `affiliationId`를 함께 유지한다.
- 같은 대학의 학부/학사·언어교육원·대학원은 별도 상담 항목·별도 이력이다.
- 차단·해제 상태도 `studentId + universityId + affiliationId`별로 표시한다. 한 소속구분의 차단은 다른 소속구분에 영향을 주지 않는다.
- D-017 프로토타입에서는 모든 현재 대학이 공개된다. 소속구분 더미가 없는 대학의 `undergraduate`도 유효한 전달값으로 처리한다. 이 기본값을 실서비스 규칙으로 저장하지 않는다.

## 경계

- 문서 요청·업로드·전달은 학생·학교 공동 기능이다.
- 어드민은 학생 문서를 열람하지 않으며, 문서 전송 화면도 만들지 않는다.
- 학생 스쿼드는 학교 인박스·공개 대학 탐색 화면을 수정하지 않는다.

## 3. 플랫폼 공지사항 — D-020

- 상태: 구현 반영, 사용자 화면 검수 대기
- 우선순위: P1
- PM: 로그인 학생은 프로필 메뉴의 `공지사항`에서 플랫폼 공지를 확인한다. GNB와 하단 탭은 추가하지 않는다.
- Designer: 중요 공지 상단 강조, 목록·본문 2패널, 모바일 1열, 게시 공지 없음 상태를 적용한다.
- Developer: `student-desktop.html`이 `notice-data.js`의 학생·전체 대상 `published` 공지만 표시한다. `student-mobile.html`은 기존 통합 반응형 화면 이동을 유지한다.
- 수용 기준: 대상이 학생 또는 전체인 게시 공지만 표시됨; 중요 공지가 최상단임; 프로필 메뉴에서 진입 가능함; 760px 이하에서 목록·본문이 1열로 배치됨.

## 4. 로그인 학생 GNB·모바일 통합 메뉴 — D-021

- 상태: 구현 반영, 사용자 화면 검수 대기
- 우선순위: P1
- PM: 로그인 학생 상태에서는 `학교 서비스`를 숨기고 로그아웃 상태에서만 표시한다. 학생 인증 상태와 개인 목적지를 공통 GNB에 제공한다.
- Designer: 760px 이하에서는 별도 프로필 버튼을 숨긴다. 햄버거에 `대학 탐색·내 상담·콘텐츠`, 학생 이름·이메일, `공지사항·문서 보관함·마이페이지·로그아웃`, 언어 선택을 순서대로 배치한다.
- Developer: `student-session.js`가 공개·학생 헤더에 같은 로그인 상태를 적용하고, `student-desktop.html` 반응형 메뉴가 같은 목적지를 사용하도록 구현한다.
- 수용 기준: 로그인 뒤 학교 서비스가 보이지 않음; 로그아웃 뒤 다시 보임; 모바일 햄버거에서 모든 페이지·개인·언어 메뉴에 접근 가능함; 햄버거 밖 프로필·언어 선택이 중복되지 않음; Escape와 바깥 클릭으로 메뉴가 닫힘.

## 5. 문서 표기·웰컴 채팅·대학 채팅 재개 — D-023

- 상태: P1 실행
- PM: 문서함의 사용자 표기 `아포스티유`를 `공증문서`로 바꾸되 기존 내부 분류값·요청 문서 호환은 유지한다. 최초 상담은 소속구분별 대학 웰컴 메시지 1회가 학생 첫 메시지 전에 표시된다. 대학이 종료 채팅을 재개하면 학생은 별도 시스템 메시지와 진행 상태를 본다.
- Designer: 문서함·업로드·문서 요청·기존 문서 선택의 표기를 통일한다. 최초 웰컴과 대학 재개는 발신자·시간·상태를 구분하되 경고처럼 보이지 않게 한다.
- Developer: `student-desktop.html`, `student-mobile.html`에서 표기 매핑, 최초 웰컴 시나리오, 대학 재개 이벤트 렌더링을 소속구분 채널별로 구현한다.
- 수용 기준: 학생 화면에 `아포스티유` 표기 없음; 최초 상담과 대학 재개가 다른 시스템 메시지로 보임; 재개 뒤 학생 입력이 가능함.
