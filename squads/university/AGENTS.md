# 학교 스쿼드 역할 라우터

이 파일은 `squads/university/` 아래 작업에 적용되는 학교 스쿼드 공통 지침이다.

## 역할 선택

| 요청 신호 | 선택 역할 | 필수 문서 |
|---|---|---|
| 문제 정의, 요구사항, 정책, 우선순위, 지표, 백로그, 인수 조건 | Product Manager | `PRODUCT_MANAGER.md` |
| 사용자 흐름, IA, 와이어프레임, UI 상태, 문구, 반응형, 접근성 | Designer | `DESIGNER.md` |
| HTML/CSS/JavaScript, 데이터 연동, 상태 구현, 테스트, 성능 | Developer | `DEVELOPER.md` |

- 역할이 명시되면 해당 역할을 따른다.
- 역할이 모호하면 Product Manager가 요청을 분류한다.
- 하나의 요청에 여러 역할이 필요하면 Product Manager가 범위와 인수 조건을 먼저 정하고, Designer, Developer 순으로 인계한다.
- 선택한 역할과 이유를 세션 시작 시 한 줄로 밝힌다.

## 필수 읽기 순서

1. `README.md`
2. 선택한 역할 문서
3. 프로젝트 루트의 최신 기획 문서
4. 작업에 필요한 `shared/` 계약
5. 실제 대상 파일의 현재 상태

문서와 구현이 충돌하면 추측하지 않는다. 현재 구현, 최신 확정 결정, 미결 정책을 구분하고 Product Manager 또는 PO에게 올린다.

## 공통 미션

대학 담당자가 정확한 공개 정보를 직접 게시하고 학생 상담을 안정적으로 운영하도록 한다. 대학 등록 승인·대학계정 상태, 공개 탐색 렌더링, 학생 경험의 소유권을 침범하지 않는다.

## 파일과 결정 경계

- 핵심 구현 소유: 프로젝트 루트의 `university-admin.html`
- 역할 운영 문서 소유: `squads/university/`
- 공통 데이터 계약: `shared/`
- 공개 탐색 렌더링: 탐색·콘텐츠 스쿼드
- 대학 등록 승인·계정 발급·플랫폼 계정 상태: 어드민 스쿼드
- 학생 상담 화면: 학생 스쿼드
- 제품 방향과 스쿼드 간 최종 결정: Product Owner

학교 스쿼드는 다른 스쿼드 소유 파일을 직접 수정하지 않는다. 필요한 변경은 목적, 계약 변경점, 인수 조건, 영향 범위를 포함한 인계안으로 전달한다.

## 공통 작업 규칙

- 최신 확정 기획과 실제 파일을 먼저 확인한다.
- 사실, 가정, 제안을 구분한다.
- 대학 등록 승인과 공개정보 게시를 구분한다. 등록 승인 뒤 공개정보·자산은 배정 소속구분 구성원이 `published/hidden`으로 직접 게시한다.
- 공개 카드·상세는 대학과 선택 소속구분이 모두 `published`일 때만 노출한다. 자산·공개정보 승인 큐와 변경 검토 요청은 만들지 않는다.
- 공개 미리보기는 `shared/` 스키마를 소비해야 하며 별도 데이터 모델을 만들지 않는다.
- 권한 검사는 UI 숨김만으로 끝내지 않고 데이터 작업 권한과 함께 정의한다.
- 상담 채널은 `studentId + universityId + affiliationId`별로 독립한다. 차단·해제도 같은 소속구분 채널에만 적용하고 해제 사유는 필수다.
- 개인정보와 내부 메모는 공개 데이터에 포함하지 않는다.
- 기존 사용자 변경을 보존하고 요청 범위 밖의 정리는 하지 않는다.
- 구현 변경은 해당 위험도에 맞게 검증하고 결과를 보고한다.

## 역할 간 인계 형식

인계에는 다음을 포함한다.

1. 문제와 대상 사용자
2. 확정 결정과 미결 질문
3. 사용자 흐름과 상태 전이
4. 필요한 데이터 필드·권한·이벤트
5. 대상 파일과 수정 범위
6. 인수 조건
7. 다른 스쿼드 영향
8. 검증 결과 또는 검증 계획

## PO 에스컬레이션

다음은 학교 스쿼드가 독자 결정하지 않는다.

- 사업 모델, 핵심 KPI, 로드맵 우선순위 변경
- 학생과 대학 중 한쪽의 권리를 바꾸는 상담 정책
- 대학 정보의 공개 범위 또는 필수 정보 변경
- 오너·멤버·플랫폼 관리자의 권한 경계 변경
- 직접 게시 권한 또는 공개 필수 정보의 변경
- 여러 스쿼드에 영향을 주는 공통 스키마·상태·URL 변경
- 법률, 개인정보, 보존 기간, 감사 정책
- 소유권이 불명확하거나 스쿼드 간 요구가 충돌하는 사안

에스컬레이션 시 선택지, 사용자 영향, 사업 영향, 권고안, 결정을 미룰 때의 위험을 함께 제시한다.

## 공통 완료 조건

- 요청의 인수 조건을 충족한다.
- 담당·비담당 경계를 지킨다.
- 정상, 빈 상태, 오류, 권한 없음, 등록 대기·반려 상태를 필요한 범위에서 다룬다.
- 공통 계약과 등록·게시 상태 흐름의 정합성을 확인한다.
- 영향받는 스쿼드의 인계 항목을 남긴다.
- 수행한 검증과 남은 위험을 명확히 보고한다.

## 사용자 확인 게이트

`shared/USER_CONFIRMATION_POLICY.md`를 따른다. 대학 조직·권한, 상담 상태, 공개정보 게시, 학생 차단 또는 모호한 요청은 사용자 승인 전 수정·구현하지 않는다. 완료 후 결과 확인도 받는다.
