## 완료한 학교 소유 구현

### 대학 운영 관리

- 대학별 최고관리자 1명, 소속구분 관리자·멤버의 복수 소속구분 배정을 목업에 반영했다.
- 최고관리자는 전체 대학·소속구분·멤버를 관리하고, 소속구분 관리자와 멤버는 배정된 모든 소속구분만 다루도록 화면 범위를 나눴다.
- `대학(학부/학사)`, `언어교육원`, `대학원`을 같은 운영 폼의 탭으로 구성했다.
- 소속구분별 상세 소개, 학과·지원 과정, 기숙사·장학금, 웰컴 메시지·이미지, 상담 채널 상태를 입력·미리보기할 수 있게 했다.
- 구미대학교 기본 상세 소개에 학교소개, 교육 성과, 5개 교육 분야를 구조화해 반영했고 콘텐츠 스쿼드 인계 스냅샷에도 같은 공개 문구를 기록했다.
- 배경 이미지·학교 로고는 파일 업로드로, 소개 사진과 모집 브로셔는 각각 최대 5개까지 누적 업로드로 구성했다. 소개 사진은 대표 사진 1개를 설정할 수 있고, 자산별 미리보기·삭제 확인을 제공한다.
- 자산 승인 큐 없이 대학 운영 화면에서 직접 게시하는 D-014 흐름을 반영했다. 대학과 선택 소속구분이 모두 `published`일 때만 공개 카드·상세에 노출되는 공통 계약 소비를 인계한다.

### 대학 운영 홈

- 권한별 메뉴 구조와 홈을 구성했다.
- 학교 캘린더·To-do 목록을 모든 권한의 홈 상단에 두고, 상세 화면은 브레드크럼으로 진입하게 했다.
- 최고관리자 홈에는 소속구분별 상담 현황을, 멤버 홈에는 개인 업무 범위와 채팅 목록을 반영했다.
- 담당자별 응대 현황의 페이지 크기(10·15·20)와 페이지네이션, 일별 상담 현황의 일·월·년 단위 선택을 반영했다.

### 상담 인박스

- 1차 탭을 `전체 채팅 · 내 상담 · 중요 채팅 · 차단 목록 · 종료`로, 전체 채팅의 2차 상태 필터를 `미배정 · 진행 중`으로 구성했다. 기존 미배정·진행중 흐름은 제거하지 않았다.
- 개인 중요 표시와 중요 채팅 목록을 반영했다. 중요 채팅은 진행 중 상담만 표시하는 기준이다.
- 상담 식별자·개인 중요 표시를 `studentId + universityId + affiliationId` 채널 키로 분리했다. 같은 학생의 학부·어학원 상담은 목록·대화 이력이 별도 항목으로 보인다.
- 모든 대학 구성원이 배정 소속구분 채널에서 학생을 차단·차단 해제할 수 있게 했다. 차단 사유는 선택, 해제 사유는 필수이며 기존 대화는 열람 가능하다. 차단·해제는 해당 소속구분 재상담에만 영향을 주고 감사 payload에 채널 식별자를 전달한다. 열람 로그 표시는 제거했다.
- 학생 정보 패널에 이메일 직접 표시, 수신 문서 분류·날짜·미리보기, 담당자·과거 대화 담당자, 자료 요청, 최신 3개 첨부파일·링크 및 더보기 모달 검색을 반영했다.
- D-018에 따라 동일 소속구분 채널에서 수신 문서를 재요청할 수 있고, 학생 재전송 시 우측 패널에 `업데이트됨`·빨간 점으로 표시한다. 구미대학교 언어교육원 채널에는 `TOPIK_4급_성적표_수정본.pdf` 시연 데이터를 기본 제공한다.
- 상담 목록 내부에 검색을 배치하고, 데스크톱·좁은 뷰에서 목록·대화·학생 정보 패널을 각각 독립 스크롤하게 조정했다.

### 반응형·샘플 데이터

- 학교 프로토타입의 샘플 대학명을 구미대학교로 교체했다. 다른 스쿼드 소유 데이터·화면은 변경하지 않았다.
- 구미대학교 공개 스냅샷(3개 소속구분·공개 문구·지역)을 콘텐츠 스쿼드에 `CR-2026-07-29-gumi-university-public-content-sync.md`로 인계했다. 계약 v2 확정 전에는 학교 내부 실행 상태를 공유하지 않는다.
- 사용자 제공 로고·배경·소개 사진 5장·모집 브로셔를 학교 프로토타입 자산 경로에 고정 연결했다. 새로고침 뒤에도 대학 운영 관리와 자산 미리보기에 유지된다.
- 좁은 화면에서 좌측 메뉴는 아이콘형으로 축소하고, 대화 작업은 더보기 메뉴로 접근하도록 했다. 각 패널은 화면 전체 높이를 강제하지 않고 내부 스크롤로 동작하게 했다.

## 스쿼드 간 인계·PO 확인 필요

1. 공개 상세 계약: `university-publication` v2 본문은 필수 검토 대기다. 계약 확정 전 메인 화면이 학교 내부 `operatingProfiles`를 직접 소비하면 안 된다.
2. 공개 렌더링: 메인·탐색·콘텐츠 스쿼드는 대학·소속구분 `published` 조건과 선택 `affiliationId`를 보존해 카드·상세·빈 상태를 렌더링해야 한다.
3. 상담 채널: 학생·메인 스쿼드는 `studentId + universityId + affiliationId` 독립 채널·독립 이력과 배정 소속구분 열람 범위를 적용해야 한다.
4. 문서: D-018의 시연 데이터는 학생 재전송 완료를 나타내는 학교 패널 fixture다. 실제 학생 문서 등록·전달·접근 실패 처리는 학생 스쿼드 소유이며, 두 화면은 `studentId + universityId + affiliationId`를 유지한다.
5. 차단 이력: 어드민은 차단·해제 감사 이력에 행위자·시각·대상·`universityId`·`affiliationId`·해제 사유를 저장한다. 학교 화면에는 열람 로그를 표시하지 않는다.
