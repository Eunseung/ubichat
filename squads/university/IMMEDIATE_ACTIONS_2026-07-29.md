# 학교 스쿼드 즉시 실행 — 2026-07-29

- 상태: 사용자 확정 정책 반영, P1 실행
- 근거: D-008, D-014, D-015, D-016, D-017, D-018
- 담당: 학교 PM → Designer → Developer

## 1. 역할과 직접 게시

- 최고관리자는 대학당 1명이다.
- 소속구분 관리자와 멤버는 여러 소속구분에 동시에 배정될 수 있다.
- 최고관리자·소속구분 관리자·멤버 모두 배정된 소속구분의 공개정보·로고·배경·사진·브로셔를 직접 `published/hidden` 처리한다.
- 대학 등록 승인과 대학계정 발급은 어드민, 공개정보·자산의 사전 승인은 없음으로 분리한다.
- D-017 프로토타입에서는 현재 대학을 모두 `published`로 표시한다. 소속구분 더미가 없는 대학의 `undergraduate` 기본값은 메인 시연용이며 학교의 실서비스 공개 데이터로 저장하지 않는다.

## 2. 소속구분별 독립 상담·차단

- 인박스·상담 이력·권한 검사는 `studentId + universityId + affiliationId` 기준으로 분리한다.
- 관계자는 배정된 소속구분의 학생 상담만 열람·응대한다. 복수 배정자는 각 소속구분의 독립 항목을 모두 본다.
- 차단·차단 해제도 같은 기준이며 해제 사유는 필수다.
- 해제 안내는 “해당 소속구분에서만 다시 상담 가능”으로 표시한다. 구현 문구는 반영 완료했다.

## 3. 학생 서류 요청·수신

1. 학교가 해당 소속구분 상담 채널에서 문서를 요청한다.
2. 학생이 등록한 같은 유형 문서가 있으면 즉시 수신한다.
3. 없으면 학생 업로드 후 같은 요청으로 전달받는다.
4. 학교는 요청·수신·실패 상태를 보여 주되, 어드민으로 문서를 전달하거나 열람 권한을 만들지 않는다.
5. 이미 수신한 문서에는 대화 우측 패널에서 `재요청하기`를 제공한다. 재요청 뒤 학생은 새 PDF 업로드 또는 같은 유형의 기존 문서를 다시 전송할 수 있다.
6. 학생이 재전송하면 같은 `studentId + universityId + affiliationId` 우측 패널에서 빨간 점과 `업데이트됨` 상태를 표시한다.

## 4. 공개정보 공통 형식 검토

- `affiliationId`는 학부/학사·언어교육원·대학원을 구분하는 소속구분 식별값이다.
- `university-publication` v2는 학교 공개정보를 메인·학생 화면에 전달하는 공통 데이터 형식이다.
- 기존 단일 관리자 값 `unitOwnerId`는 복수 관리자를 담을 수 없으므로 `unitOwnerIds[]` 전환안을 검토한다. 계약 본문 변경은 필수 검토 완료 뒤에만 진행한다.

## 수용 기준

- 공개 대학·소속구분이 모두 `published`일 때만 외부 카드용 데이터를 생산한다.
- 멤버를 포함한 배정 관계자가 직접 게시할 수 있다.
- 학생의 요청 문서 수신과 미등록 문서 업로드 후 수신이 같은 상담 채널에 연결된다.
- 수신 문서 재요청·재업로드·업데이트 알림이 같은 소속구분 채널을 벗어나지 않는다.

## 5. 플랫폼 공지사항 — D-020

- 상태: 구현 반영, 사용자 화면 검수 대기
- 우선순위: P1
- PM: 최고관리자·소속구분 관리자·멤버 모두 학교 대상 플랫폼 공지를 읽는다. 학교 작성 기능은 제공하지 않는다.
- Designer: 홈 운영 도구를 넓은 데스크톱에서 캘린더·To-do·공지 3열로 배치한다. 1180px 이하는 2열, 800px 이하는 1열로 전환한다.
- Developer: 홈 위젯은 최근 공지 3개와 중요 표시를 제공하고, `전체 보기`는 목록·본문을 표시한다. `notice-data.js`의 학교·전체 대상 `published` 공지만 사용한다.
- 수용 기준: To-do와 공지가 동시에 보임; 모든 학교 역할에서 동일하게 읽을 수 있음; 중요 공지가 최상단임; 작성·수정 버튼이 없음; 모바일 1열이 유지됨.

## 6. 공개 상세·채팅 운영 보완 — D-023

- 상태: P1 실행
- PM: `입학 안내 자료`는 PDF만 받는다. 공개 상세 기본 탭은 `상세 소개·학과 정보·지원 과정·기숙사 소개·기숙사 사진`이며, 탭은 제목·본문·순서·활성 상태를 가진다. 추가 탭도 같은 형식으로 관리한다. 종료 채팅은 배정된 소속구분 관계자만 재개할 수 있다. 차단 사유는 `광고성 채팅·어뷰징 유저·기타`; `기타`만 상세 사유 입력이 필수다.
- Designer: PDF 오류·교체 상태, 탭 추가·수정·순서·활성 토글·삭제 확인, 기숙사 사진 없음·1장·복수 캐러셀, 종료 채팅 `다시 시작`, 차단 사유 선택·조건부 텍스트 입력을 설계한다.
- Developer: `university-admin.html`에서 PDF MIME·확장자 검증, 탭·사진 데이터, 종료→진행중 재개와 학생 시스템 이벤트, 차단 사유 enum·상세 검증을 구현한다. 공개 탭·재개 상태를 메인·학생에 인계한다.
- 수용 기준: PDF 외 입학 안내 자료 업로드 불가; 활성 탭만 공개 상세에 순서대로 노출; 기숙사 사진 캐러셀 동작; 대학 재개 뒤 학생·학교가 같은 진행 상태·시스템 메시지를 확인; 차단 사유 선택 필수 및 기타 상세 사유 필수.
