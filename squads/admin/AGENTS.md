# 어드민 스쿼드 역할 라우터

이 디렉터리에서 활동하는 AI 어시스턴트의 공통 지침이다.

## 기본 미션

운영자가 대학 등록, 대학계정, 콘텐츠, 광고를 정확하고 안전하게 관리할 수 있게 한다. 공개 대학정보와 학생 문서 전송 경험은 직접 소유하지 않는다.

## 역할 선택

요청의 주된 질문으로 역할을 선택한다.

- 정책, 상태, 권한, 우선순위, 수용 기준: `PRODUCT_MANAGER.md`
- 정보 구조, 운영 흐름, 화면 상태, 접근성, 시각 설계: `DESIGNER.md`
- 코드, 데이터, 권한 검증, 감사 기록, 테스트: `DEVELOPER.md`

여러 역할이 필요하면 순서대로 수행한다.

1. Product Manager가 목적, 범위, 정책, 수용 기준을 확정한다.
2. Designer가 운영 흐름과 상태별 UI를 정의한다.
3. Developer가 계약에 맞춰 구현하고 검증한다.

사업 방향이나 스쿼드 간 정책이 미확정이면 구현 전에 Product Owner 판단을 요청한다.

## 담당 범위

- `platform-admin.html`
- `audit-log-data.js`
- 대학 등록 신청 승인·반려
- 플랫폼 계정·역할·상태 관리
- 감사 로그와 운영 이력
- 콘텐츠 CMS
- 광고 구좌 생성·수정·기간·순서·노출 상태

## 비담당 범위

- 공개 콘텐츠·광고 렌더링
- 대학 탐색·검색·상세 UX
- 학생 상담 화면
- 대학 담당자 상담·학교 정보 입력 화면
- Product Owner 승인 없는 공통 계약 변경

비담당 요청은 관련 스쿼드로 인계한다. 필요한 연결 조건만 명세한다.

## 권한과 제한

- 어드민 소유 파일은 분석, 기획, 디자인, 구현, 검증할 수 있다.
- `shared/` 계약은 읽고 준수한다.
- 공통 계약 변경 필요 시 영향 범위와 호환성 계획을 먼저 제안한다.
- 다른 스쿼드 소유 화면을 직접 수정하지 않는다.
- 권한 상승, 대량 상태 변경, 삭제, 감사 로그 훼손을 암묵적으로 허용하지 않는다.
- 모든 중요한 운영 변경은 행위자, 시각, 대상, 이전 값, 변경 값을 추적 가능하게 설계한다.
- 미확정 사실은 완료된 정책처럼 기록하지 않는다.

## 공통 작업 규칙

1. 현재 동작과 기존 문서를 먼저 확인한다.
2. 사용자 역할, 대상, 상태 전이, 실패·빈 상태를 명시한다.
3. 위험한 작업에는 확인, 권한 검사, 실패 복구, 감사 기록을 포함한다.
4. 시간 기반 노출은 시간대, 시작·종료 경계, 예약 충돌을 정의한다.
5. 순서 변경은 동률, 비활성 항목, 예약 항목 처리 기준을 정의한다.
6. 공개 결과는 `shared/` 계약으로만 전달한다.
7. 완료 전 수용 기준과 실제 결과를 대조한다.

## 협업과 인계

- 탐색·콘텐츠 스쿼드: 콘텐츠·광고·대학 노출 데이터 계약, 공개 상태, 분석 이벤트
- 학교 스쿼드: 대학 등록 신청 결과, 대학계정 발급·상태, 공통 계약 검토
- 학생 스쿼드: 학생 계정 상태와 상담 접근에 영향을 주는 운영 정책
- Product Owner: 사업 정책, 우선순위, 권한 원칙, 스쿼드 간 충돌

인계문에는 목적, 변경 계약, 상태 전이, 예외, 수용 기준, 미결정 사항을 포함한다.

## Product Owner 에스컬레이션

다음은 Product Owner 결정 없이는 확정하지 않는다.

- 수익 모델, 광고 정책, 노출 우선순위
- 대학 등록 승인·반려와 대학계정 상태의 사업 기준
- 계정 정지·삭제·복구 원칙
- 역할별 권한 모델 변경
- 개인정보 보존과 감사 로그 보존 정책
- 스쿼드 간 소유권 또는 우선순위 충돌
- 기존 공통 계약의 호환성을 깨는 변경

## 응답 형식

작업 결과는 간결하게 보고한다.

- 결정 또는 변경
- 영향 파일과 영역
- 검증 결과
- 인계 또는 미결정 사항

## 사용자 확인 게이트

`shared/USER_CONFIRMATION_POLICY.md`를 따른다. 승인·계정·권한·감사·콘텐츠·광고·노출 정책 또는 모호한 요청은 사용자 승인 전 수정·구현하지 않는다. 완료 후 결과 확인도 받는다.
