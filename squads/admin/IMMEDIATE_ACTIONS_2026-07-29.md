# 어드민 스쿼드 즉시 실행 — 2026-07-29

- 상태: 사용자 확정 정책 반영, P1 실행
- 근거: D-008, D-014, D-015, D-016, D-017, D-018
- 담당: 어드민 PM → Designer → Developer

## 1. 대학 등록·대학계정

- 대학 등록 신청의 승인·반려를 제공한다.
- 최고관리자, 소속구분 관리자, 멤버 계정을 모두 발급할 수 있게 한다.
- 최고관리자는 대학당 정확히 1명으로 보호한다. 소속구분 관리자·멤버의 복수 소속구분 배정을 지원한다.
- 대학계정의 활성·비활성 상태를 관리한다.
- D-017 프로토타입의 현재 대학은 모두 공개 상태로 읽기 전용 표시한다. 공개 상태를 변경하거나 승인하지 않는다.

## 2. 명확한 비범위

- 학교 공개정보·로고·브로셔·사진의 사전 승인 화면을 만들지 않는다.
- 학생의 서류 요청, 등록 문서 즉시 전송, 미등록 문서 업로드 후 전달을 만들지 않는다.
- D-018의 수신 문서 재요청, 학생 재업로드, 학교 우측 패널 업데이트 알림도 학생·학교 범위다.
- 학생 문서 원본·메시지 본문은 열람하지 않는다.
- 차단 해제 사유는 학교 상담 채널의 필수 입력이다. 이번 즉시 작업에는 어드민 차단 이력 화면을 넣지 않는다.

## 3. 공통 형식 검토

- `university-publication` v2 검토자로서 복수 소속구분 관리자·멤버, 소속구분 공개 상태, `affiliationId` 전달이 대학계정 정책과 충돌하지 않는지만 확인한다.
- `affiliationId`는 같은 대학의 각 소속구분을 구분하는 내부 값이다.

## 수용 기준

- 운영자는 세 역할의 대학계정을 발급할 수 있다.
- 공개정보 게시 승인 없이 학교가 직접 게시한다.
- 어드민 화면에서 학생 문서 전송·열람 기능이 노출되지 않는다.

## 4. 플랫폼 공지사항 — D-020

- 상태: 구현 반영, 사용자 화면 검수 대기
- 우선순위: P1
- PM: 공지는 공개 콘텐츠 CMS와 분리하며 대상은 학생·학교 전체, 학생, 학교다. 상태는 게시 예정·게시 중·종료다.
- Designer: 별도 `공지사항` 메뉴에서 상태·대상·중요 여부·최근 변경·관리 동작을 한 화면에 제공한다.
- Developer: `notice-data.js`를 소유하고 작성·수정·게시·종료를 제공한다. `published`만 대상 포털에 전달하고 종료는 삭제 없이 `hidden`으로 저장한다.
- 수용 기준: 플랫폼 어드민만 작성 가능함; 대상별 포털 노출이 분리됨; 중요 공지가 소비 화면 최상단에 표시됨; 종료 공지가 즉시 숨겨지고 관리 화면에는 남음.

## 5. 내부 보고 수정사항 검토 — D-023

- 상태: P1 검토
- PM: 공지 GNB 추가 뒤에도 공지 대상·로그인 열람·플랫폼 어드민 단독 작성 권한을 유지하는지 검토한다.
- Designer: 공개 공지 본문을 새 화면으로 만들지 않는다. 정적 배포에서 학교·어드민의 로고 링크가 `index.html` 메인으로 복귀하는지 확인한다.
- Developer: 차단·채팅 재개 감사 데이터에 행위자·시각·소속구분·선택 사유·기타 상세 사유가 남는지 검토한다. 학생 문서 열람·학교 공개정보 사전 승인 기능은 추가하지 않는다.
- 수용 기준: 비로그인 공지 본문 노출 없음; 작성 권한은 어드민만 유지; 감사 데이터 누락 없음.

## 6. 구미대학교 공개정보 동기화 경계 검토 — D-026

- 상태: P1 검토
- PM: 구미 공개정보는 학교가 직접 게시하며, 어드민은 대학 등록 승인·대학계정 발급만 수행한다.
- Designer·Developer: 공개정보 승인 큐, 수정 화면, 동기화 대시보드, 학생 문서 연동을 만들지 않는다. 정적 프로토타입 저장 키가 대학계정 상태·감사 데이터에 노출되지 않는지 확인한다.
- 수용 기준: 어드민 화면에 구미 공개정보 승인·편집 기능 없음; 학교 직접 게시 권한과 대학 등록 승인 경계 유지.
